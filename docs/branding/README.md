# clued branding

The mark is a thread with a marker for each state a request goes through: queued, working, waiting on you, answered. The name is always lowercase: clued.

## Files

| File | What it is | Size |
|---|---|---|
| `logo-light.png` | Full logo (mark and wordmark) for light backgrounds, transparent | 2033 × 773 |
| `logo-dark.png` | Full logo for dark backgrounds, transparent | 2035 × 773 |
| `mark-light.png` | Simplified square mark on a light rounded tile, for favicons and avatars | 1024 × 1024 |
| `mark-dark.png` | The same mark on a dark tile (#161b22) | 1024 × 1024 |
| `social-preview.png` | GitHub social preview: logo and tagline on #0d1117 | 1280 × 640 |

The README shows `logo-light.png` or `logo-dark.png` with a `<picture>` element that follows the reader's colour scheme.

## Palette

| Colour | Hex | Use |
|---|---|---|
| Grey | `#9CA3AF` | queued |
| Blue | `#3B82F6` | working |
| Amber | `#F59E0B` | waiting on you |
| Green | `#22C55E` | answered (with a white check) |
| Indigo | `#312E81` | wordmark and thread on light backgrounds |
| White | `#FFFFFF` | wordmark on dark backgrounds |
| Light grey | `#D1D5DB` | thread on dark backgrounds |
| GitHub dark | `#0D1117` | dark background |

Colours are flat: no gradients, shadows or glows. The images are raster drawings, so the colours in them are close to these values, not exact.

## Font

[Rubik](https://fonts.google.com/specimen/Rubik) (Google Fonts, free), heavy weight, lowercase. The wordmark in the images is drawn, not set in the font, so Rubik is the font to use next to it, for example in a banner or a slide.

## Where the images come from

ChatGPT generated these images with its image generation, from a brief written for clued. The square marks and the social preview were then finished by ChatGPT's own editing (clean transparent edges, the dark recolour, the exact 1280 × 640 canvas). The only change made here is lossless PNG optimisation (oxipng), which leaves every pixel the same. It also removes the C2PA provenance data ChatGPT embeds, because re-encoding the file would make that data's signature fail to verify.
